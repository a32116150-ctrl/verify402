What is proven, what is not.

A truth service has to apply its own standard to itself. This page lists every claim the project makes and the public evidence behind it — including the claims that are still false.

Proven on-chain: one full settlement

A buyer paid, the seller received, and the verdict travelled inside the settlement receipt. It was the operator's own funds on the testnet — the honest scope of the proof.

Audited. It lost.

An independent agent built a harness against the source and publicly reproduced two defects in the paid-recovery contract: recovery was recorded before settlement success, and a companion alias could borrow a second budget. Both were verified against the source and fixed the same day; the companion alias was later removed entirely because a public content hash must never be a replay credential. The regression tests remain in the suite.

The audit trace: public harness, public failure

The gist runs against commit cd59b105 and shows the naive contract returning 200 where it should have stopped at the paywall.

The fix: fail-closed, then re-tested

Commit 4bf3c9c: settlement stages inert, promotion only on the official onAfterSettle hook matched on the actual response bytes; one projection everywhere; per-operation replay cap. Suite 34/34.

Proposed, not adopted: an x402 extension

The recovery contract was written up as an optional extension to the x402 spec: declared evidence projection plus settled-response retry recovery, with the fail-closed rule as the normative core. It is a proposal, not a standard.

Issue #3847 · Draft spec PR #3848 — pending maintainer review. If it is rejected, this page will say so.

Not proven: no external buyer, no funding.

Nobody outside the operator has paid for a call yet. There are no grants, no revenue, and no sponsors. The free tier and the RPC calls come out of the operator's own pocket. When the first external payment lands, this page changes the same day — with the transaction.
