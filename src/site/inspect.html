Inspect by URL

Paste an x402 endpoint.

The inspector sends one unpaid request, reads the 402 challenge, and runs the payment preflight on each option. It does not forward cookies, auth headers, or a wallet.

Ready

Only public http(s) hosts are fetched: localhost, private ranges, and redirects are refused. The response is capped at 64 KB. The sample takes POST, so POST is preselected; a POST sends an empty {} body. A slow endpoint can take a few seconds.

Advanced: paste a 402 challenge instead

No fetch is made in this mode. Paste what curl -i showed you. Do not paste private keys or seed phrases.

curl -s -X POST https://verify402.onrender.com/inspect \
  -H 'content-type: application/json' \
  -d '{"url":"https://verify402.onrender.com/verify","method":"POST"}'

      Built for the x402 ecosystem. The inspector is free because it has to run before every payment. The paid checks stay paid. How the gate decides
      
          
      The 402 is not proof that the seller controls the payee. The inspector says what it verified and what it did not.
      
        
      
      
      
    
      
  
      

  
      
    
      
      
      
        
      
          
      What it checks
      
          
      The same gate, pointed at a real 402.
      
          
      Every option in the challenge goes through the structural payment preflight. The inspector adds three checks that only make sense with a target URL, then reports one verdict.
      
        
      
      
      
      
      
        
      
          1
          
      The money
      
          
      Scheme, network, asset, amount, and payee. A canonical USDC asset on a supported network, a non-zero non-burn payee, and an amount inside the policy.
      
        
      
        
      
          2
          
      The binding
      
          
      The challenge's resource must name the URL you asked about. If the response is not a 402, the inspector says so instead of pretending it checked a paywall.
      
        
      
        
      
          3
          
      The options
      
          
      Every accept is checked. Several payees, a missing resource, an unknown token, or a zero amount each become a typed reason — never a silent pass.
      
        
      
      
      
      
      
        
      What the fetch can and cannot do
      
        
      The URL is resolved first, every resolved address must be public, and the connection is pinned to that address — so a second DNS answer cannot point it at localhost. Redirects are refused, the body is capped at 64 KB, and the request carries no credentials. The response is treated as untrusted data. The fetch is still a best-effort guard on a shared host; the pasted-challenge mode makes no request at all.
