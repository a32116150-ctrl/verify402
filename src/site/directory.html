Live watch · no wallet

Known x402 endpoints, watched.

A small public list, re-inspected every 15 minutes. Each entry carries two verdicts: protocol — is the challenge well-formed x402? — and sign — should an agent on our supported networks sign it? Most live 402s sit on chains this instance cannot verify, so sign is often BLOCK while protocol is PASS. Both are shown, and changes are recorded.

Two verdicts, one reason

Protocol ≠ permission.

A challenge can be perfectly formed and still be unpayable by this gate. The directory keeps those answers apart so a BLOCK never hides a well-formed endpoint, and a PASS never implies a safe seller.

Protocol

Is it well-formed?

Accepts present, scheme exact, amount positive, payee named and not the burn address, resource bound over https, expiry parseable, no duplicate payees on one network. Network-agnostic.

Sign

Should our agent sign?

The same structural payment preflight an agent runs before signing, on this instance's supported networks. A canonical USDC asset, a sane amount, a payee the policy allows.

Watch

What changed?

Status, price, payee, network, and both verdicts are diffed on every refresh. A price jump or a payee swap shows up as a change row, not a silent rewrite.

Limits, stated plainly

The directory only inspects public endpoints with no authentication. It cannot see paywalls behind an API key, a logged-in session, or a private network. History is process-local unless VERIFY402_DIRECTORY_FILE is set; on a free host that file is ephemeral, so a restart starts a fresh history and re-inspects the seeds. A BLOCK is a refusal to sign, not a verdict on the seller's honesty.

Keep the watch running.

The directory and the inspector are free. The mainnet cutover — where the gate can verify real payments instead of testnet — is funded by one-month sponsorships. No token, no equity, no influence on verdicts.
