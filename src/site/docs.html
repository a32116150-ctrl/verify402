01 · The handshake

Ask, get 402, pay, retry once.

First call without payment. The service answers 402 Payment Required with everything your agent needs: scheme, network, asset, amount, recipient, and the per-call cap.

1 · Ask without paying

curl -X POST https://verify402.onrender.com/verify \
  -H "Content-Type: application/json" \
  -H "x-idempotency-key: my-op-1" \
  -d '{"pair":"USDC/WETH","dex":"uniswap-v3","sizeUsd":100000}'

# → HTTP 402 Payment Required
#   accepts: eip155:8453 (USDC) or solana:… (USDC), payTo, amount, maxTimeoutSeconds

2 · Pay and retry with proof

# x402 clients (e.g. @x402/fetch) do this automatically:
#   read the 402 → sign the exact payment → retry with X-PAYMENT
# The retry returns the verdict with an evidence_bundle.

Send x-idempotency-key on the first call

If the connection dies after settlement, the retry with the same key replays the same bytes for free — within ten minutes, three replays max. The key is the cheapest insurance on this rail.

02 · Receipts

Every paid response can be rechecked.

The response carries an evidence bundle so a third party can recompute the measurement without trusting the service: the hash of the canonical request, the hash of the actual response body, and the pinned block.

FieldWhat it proves
requestHashThis exact request was the one answered — canonical bytes, not a paraphrase
responseHashThe exact bytes returned; a replay that doesn't match isn't free
pinnedBlockThe chain state the answer describes. Everything is a quote about one block.
verdictedge, no_edge, or no_edge_costs_ate_it

The recovery contract, in one paragraph

A settlement is staged, not recorded, when payment succeeds. It is promoted only by the official onAfterSettle hook, keyed on a server-generated operationId carried in the response and requiring a confirmed settle with a transaction reference — with the hash of the actual response bytes as an additional check. Equal output does not identify an operation: two requests that both return no_match are still distinct, and settling one never promotes the other. A failed or pending settlement promotes nothing; staged-unpromoted records age out silently after five minutes; the replay cap is per operation, shared by aliases. Reusing a key with changed request content, or from a different payer, is a 409 conflict resolved before the paywall — never the other operation's answer, never a charge. The content companion is a same-caller recovery alias, not a public cache. Two parts of this were broken in public by an independent auditor and fixed the same day: commit 4bf3c9c, then hardened after the x402 spec review (#3848).

Errors are honest too

400 means the request was malformed — the message names the field. 402 is the door, not a wall. 500 means the service failed, and it says so instead of returning a fabricated number. Verdicts are never invented to look useful.
